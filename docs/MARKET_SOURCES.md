# Market source and timestamp contract

This document describes the values shown by OpenTerminal and the evidence that may be used to call a value current. Provider response time, observation time, browser stream connectivity, and exchange event time are different facts and stay separate. A protocol name such as `sip` or `opra` does not prove the source or account entitlement.

## Source matrix

The source pairs and typed timestamps below describe the Web/Node contract when the Gateway supplies them. The current Rust Gateway baseline does not yet provide this metadata and status consistently. Legacy REST numeric values remain readable, but missing source/time identity is shown as unknown and cannot be called `LIVE`; legacy stream payloads without a verifiable Gateway instance identity do not establish a live event. Completing the Gateway protocol, ACK, and lease side is separate #3 work and is not evidenced by this Web/Node change.

## Feed status and freshness

The Web/Node layer accepts server-controlled `source_mode` and `source_label` on Gateway envelopes, snapshots/bars/options, stream events, and `feed_status`, and preserves them through its quote/history APIs. The accepted live SIP pair is `alpaca` / `Alpaca SIP`; the accepted live OPRA pair is `alpaca` / `Alpaca OPRA`. Test-only Next/Gateway fixtures use `offline_mock` / `OFFLINE MOCK — NOT MARKET DATA`. The UI displays only a recognized matching pair. Missing or mismatched fields display `source unknown`; the client never derives an Alpaca claim from `feed=sip` or `feed=opra`. The browser cannot choose the mode. FRED, SEC, FINRA, foreign listings, and explicit crypto pairs retain their own provider labels and observation times rather than being forced into this two-mode contract.

The current offline browser fixtures exercise the Next BFF and Web presentation contract; they do not exercise the Rust protocol, upstream ACK, event ordering, or effective Gateway lease set. A fixture marked `FRESH · OFFLINE MOCK` is not market data or entitlement evidence. Research prices remain provider-attributed and cannot fill missing U.S. SIP fields.

The browser reports its SSE transport separately from upstream state. Upstream authentication, desired subscriptions, pending changes, ACK-confirmed subscriptions, coverage, and freshness are independent fields. A connected browser is not proof of an authenticated or ready SIP/OPRA connection. A confirmed subscription is not proof that a fresh event has arrived.

The forward-compatible market-event contract uses nullable `event_time`, Gateway `received_at`, `gateway_instance_id`, `connection_epoch`, and a local sequence. The sequence is for ordering events published by one Gateway instance; it is not an exchange sequence. REST barriers are split by symbol and event type, with independent quote/trade source times. UI freshness is only `LIVE` when browser SSE is open, upstream transport/authentication/readiness are valid, the symbol is ACK-confirmed with complete coverage, trusted source metadata matches, and the event's source time agrees with the Gateway freshness projection. Missing source time, source identity, Gateway instance, or a legacy mixed timestamp is unknown. When supplied, `fresh_until` may make the projection expire sooner; the shared browser clock also enforces a conservative five-second display ceiling based on event time and projection age. This is a client fail-safe, not an upstream freshness policy. A connected SSE with no new market events therefore cannot keep a quote labeled `LIVE` indefinitely. The current Rust baseline does not yet emit all of these fields, so its legacy SSE does not qualify for `LIVE`.

REST snapshot watermarks are scoped to feed, symbol, and event type. The request-start sequence and per-symbol observation time protect a snapshot from being overwritten by older stream events and protect a newer tick from an older REST response. Resync or a new connection epoch clears old live values while retaining timestamped REST snapshots; retained snapshots are not labeled live.

The header shows configured SIP/OPRA feed names separately from entitlement, which remains unverified until the authenticated upstream status confirms it. Trading day and market session are shown only from the Gateway projection; when that value is missing or unknown, the header says so. Its weekday 09:30–16:00 ET indicator is explicitly an estimate and does not infer holidays or early closes. Session context does not override per-symbol event freshness: a timestamped extended-hours event may be fresh while the regular session is closed, and an old quiet-market event still becomes stale.

## Coverage fields

Market-row responses report:

- `requested`: unique U.S. SIP symbols requested;
- `snapshots`: requested symbols with a returned SIP snapshot record;
- `priced`: requested symbols with a finite price;
- `snapshotComplete`, `priceComplete`, and `timeComplete`: independent completeness checks; `timeComplete` means all returned last prices have a valid `last_as_of`, not that every quote and bar field has a timestamp;
- `complete`: true only when all three checks pass.

An Alpaca batch size is not an account entitlement limit. The displayed option `configured/local limit` is a Gateway protection setting, not an OPRA account entitlement; account entitlement remains unknown until independently verified. If the local limit is unavailable, UI displays it as unknown. Confirmed stream coverage comes only from upstream ACK and is separate from unique REST snapshot count. A snapshot object with null price or no valid source time is not complete coverage.

## Verification evidence

The server's loopback HTTP tests mount the actual Express auth middleware and market router. They check the delegated Gateway JWT, verify deliberately incorrect TradingView U.S. prices are replaced by SIP values, verify authenticated SIP 401/403/429 responses produce no public-price fallback calls, and verify an all-null SIP snapshot is not complete coverage. They distinguish an anonymous route 401 (which must not call Gateway) from an authenticated upstream 401. They also verify trusted source-mode/label propagation for SIP quote/history/market rows and the explicit offline marker, plain `BTC` stays on SIP while `BTC-USD` is normalized to Binance, U.S. history and earnings price movement use SIP bars while Nasdaq remains the EPS surprise source, and the legacy Node U.S. options route returns HTTP 410 without a public-provider call. Provider and store tests cover batching, coalescing, source classification, nanosecond/offset timestamp order, old-tick rejection, scoped REST watermarks, and freshness independent of session context.

The Playwright `market-stream.spec.ts` signs in through the local OIDC flow and exercises real Next routes with offline fixtures. It opens multiple tabs and Options widgets, verifies ACK and stale-tick behavior, waits for the regular chain snapshot poll without empty-membership cleanup, and delays an old-generation cleanup until after a newer renewal reaches the downstream mock. It treats fixture source metadata as unknown instead of claiming Alpaca. It also verifies stale/unauthorized status and browser-stream outage recovery to a newer SIP REST snapshot. The signed-in SIP 401/429 cases assert the failed `/api/quotes` request, visible widget error, Gateway request count, and absence of the research-provider fallback. The shared E2E Gateway fixture records subscription request order but always responds successfully; it does not assert the effective lease set after an out-of-order request. Rejection of stale/equal generations and the final desired membership/deadline remain #3 Gateway and Next-to-Rust container acceptance items.
