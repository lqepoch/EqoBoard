# Market source and timestamp contract

This document describes the values shown by OpenTerminal and the evidence that may be used to call a value current. Provider response time, observation time, browser stream connectivity, and exchange event time are different facts and stay separate. A protocol name such as `sip` or `opra` does not prove the source or account entitlement. OpenBB Gateway rows now carry source and field-specific observation metadata; that row adapter does not complete the separate OpenTerminal stream freshness/ACK contract.

## Source matrix

The source pairs and typed timestamps below describe the Web/Node contract when the Gateway supplies them. The earlier Rust Gateway baseline described in prior work did not provide this metadata and status consistently; that statement is historical. The current Gateway projects typed Broker ACK status for the OPRA options port, while source identity and entitlement remain unknown and no real provider evidence has been run. The legacy SIP stream still lacks a typed Broker ACK and trustworthy source timestamp. Legacy REST numeric values remain readable, but missing source/time identity is shown as unknown and cannot be called `LIVE`; legacy stream payloads without a verifiable Gateway instance identity do not establish a live event.

## Feed status and freshness

The OpenBB Gateway adapter returns row-level `source`, `source_mode`, `source_label`, and `feed`. It marks rows `alpaca` only when the built-in `https://data.alpaca.markets` endpoint is used; any configured base URL override reports `unknown`, even when the feed parameter is `sip` or `opra`. Stock `market_as_of` follows the source used for `last` (`trade` or daily bar); quote and daily-bar timestamps are separate. Option `quote_at`, `trade_at`, and `model_as_of` are separate; absent model time stays null. A bar's `market_as_of` is its source bar timestamp. These OpenBB rows do not imply that account entitlement or stream readiness has been verified.

The Web/Node layer accepts server-controlled `source_mode` and `source_label` on Gateway envelopes, snapshots/bars/options, stream events, and `feed_status`, and preserves them through its quote/history APIs. The accepted live SIP pair is `alpaca` / `Alpaca SIP`; the accepted live OPRA pair is `alpaca` / `Alpaca OPRA`. Test-only Next/Gateway fixtures use `offline_mock` / `OFFLINE MOCK — NOT MARKET DATA`. The UI displays only a recognized matching pair. Missing or mismatched fields display `source unknown`; the client never derives an Alpaca claim from `feed=sip` or `feed=opra`. The browser cannot choose the mode. FRED, SEC, FINRA, foreign listings, and explicit crypto pairs retain their own provider labels and observation times rather than being forced into this two-mode contract.

The offline browser fixtures exercise the Next BFF and Web presentation contract; the Gateway Rust unit suite separately exercises a fake Broker port's ACK/control projection, stale-generation rejection, and bounded session drain. Neither kind of fixture contacts Alpaca or proves a real account entitlement. A fixture marked `FRESH · OFFLINE MOCK` is not market data or entitlement evidence. Research prices remain provider-attributed and cannot fill missing U.S. SIP fields.

The browser reports its SSE transport separately from upstream state. Upstream authentication, desired subscriptions, pending changes, ACK-confirmed subscriptions, coverage, and freshness are independent fields. A connected browser is not proof of an authenticated or ready SIP/OPRA connection. A confirmed subscription is not proof that a fresh event has arrived.

The forward-compatible market-event contract uses nullable `event_time`, Gateway `received_at`, `gateway_instance_id`, `connection_epoch`, and a Gateway-local sequence. The sequence orders events published by one Gateway instance; it is not an exchange sequence. REST barriers are split by symbol and event type, with independent quote/trade source times. UI freshness is only `LIVE` when browser SSE is open, upstream transport/authentication/readiness are valid, the symbol is ACK-confirmed with complete coverage, trusted source metadata matches, and the event's source time agrees with the Gateway freshness projection. Missing source time, source identity, Gateway instance, or a legacy mixed timestamp is unknown. When supplied, `fresh_until` may make the projection expire sooner; the shared browser clock also enforces a conservative five-second display ceiling based on event time and projection age. This is a client fail-safe, not an upstream freshness policy. A connected SSE with no new market events therefore cannot keep a quote labeled `LIVE` indefinitely.

The Gateway now projects Broker OPRA events with separate provider `event_time` and local `received_at`, plus instance/epoch/local-sequence fields. Its typed Broker subscription ACK may confirm the exact option quote/trade channel set, but Gateway auth, source mode/label, and entitlement remain `unknown`; this does not qualify the stream as `LIVE`. The existing SIP stream adapter still has no typed Broker ACK and its legacy market DTO has no trustworthy source timestamp, so SIP stream confirmation and event time remain unknown. Gateway `/api/v1/status` keeps `market_data_ready=false`. No real provider or entitlement check was run for this integration.

REST snapshot watermarks are scoped to feed, symbol, and event type. The request-start sequence and per-symbol observation time protect a snapshot from being overwritten by older stream events and protect a newer tick from an older REST response. Resync or a new connection epoch clears old live values while retaining timestamped REST snapshots; retained snapshots are not labeled live. Gateway SSE/WS registration replays the latest status for at most the stocks and options feeds. A single publication-order lock makes receiver registration, ACK replay, sequence allocation, and broadcast sends deterministic; replay is marked `resync_required` so a reconnect cannot retain old live values, and the next quote receives a later sequence. Lag resyncs carry the latest known feed epoch rather than resetting it to zero.

The header shows configured SIP/OPRA feed names separately from entitlement, which remains unverified until the authenticated upstream status confirms it. Trading day and market session are shown only from the Gateway projection; when that value is missing or unknown, the header says so. Its weekday 09:30–16:00 ET indicator is explicitly an estimate and does not infer holidays or early closes. Session context does not override per-symbol event freshness: a timestamped extended-hours event may be fresh while the regular session is closed, and an old quiet-market event still becomes stale.

## Coverage fields

Market-row responses report:

- `requested`: unique U.S. SIP symbols requested;
- `snapshots`: requested symbols with a returned SIP snapshot record;
- `priced`: requested symbols with a finite price;
- `snapshotComplete`, `priceComplete`, and `timeComplete`: independent completeness checks; `timeComplete` means all returned last prices have a valid `last_as_of`, not that every quote and bar field has a timestamp;
- `complete`: true only when all three checks pass.

An Alpaca batch size is not an account entitlement limit. The displayed option `configured/local limit` is a Gateway protection setting, not an OPRA account entitlement; account entitlement remains unknown until independently verified. If the local limit is unavailable, UI displays it as unknown. Confirmed stream coverage comes only from upstream ACK and is separate from unique REST snapshot count. A snapshot object with null price or no valid source time is not complete coverage.

## Archived dataset bars

The read-only BFF route `/api/eqo/market-data/datasets/{dataset_id}/bars?namespace=diagnostic&symbol=QQQ` serves the MDP `lqepoch.us_equity_trade_bar_1m.v1` payload. It is separate from live Gateway snapshots, SSE and subscription state. Eqo validates the pinned schema fingerprint, exact decimal strings, event-time interval, availability time, session/window identity, source consistency and explicit finite-EOF fields before returning the response. The V1 API has no typed DatasetCompletionV2 evidence, so `namespace=curated` is rejected before calling MDP; this route currently exposes only `diagnostic` datasets.

The archive row's `bar_start_utc` and `source_start_utc`/`source_end_exclusive_utc` describe event-time facts; `available_at_utc` is the time the aggregate became available and must not be substituted for event time. `completion_mode=synthetic_eof` remains synthetic even when its schema and bytes verify. Historical EOF and page exhaustion describe finite input processing, not source-side point-in-time guarantees. `session_policy_id` and its hash record the producer's supplied window policy; Eqo does not independently validate an exchange calendar, holiday or early close. `nbbo_input_status=excluded` means quotes were not inputs to these trade OHLCV bars; the bars do not represent NBBO or market-state completeness. None of these archive facts establish current SIP/OPRA entitlement, a live feed, or an ACK-confirmed subscription.

## Verification evidence

Every market API route has an explicit `express-rate-limit` service bucket (1,200 requests per minute per Node process) and a verified-owner bucket (120 requests per minute per owner). The owner key is derived from the already-verified IdP issuer and subject; missing verified identity is rejected before the provider handler, and caller-supplied forwarding headers cannot change the owner bucket. These in-memory limits are per process and complement the existing API-wide limit; they are not a distributed account entitlement or a substitute for deployment-level traffic controls.

The server's loopback HTTP tests mount the actual Express auth middleware and full market router. They check the delegated Gateway JWT, verify deliberately incorrect TradingView U.S. prices are replaced by SIP values, verify authenticated SIP 401/403/429 responses produce no public-price fallback calls, and verify an all-null SIP snapshot is not complete coverage. They distinguish an anonymous route 401 (which must not call Gateway) from an authenticated upstream 401. A low-limit instance of the same full router factory verifies real route responses return HTTP 429 with a positive `Retry-After`, that another verified owner receives a separate bucket despite spoofed `X-Forwarded-For`, and that requests rejected by the owner or process limit make no additional Rust SIP calls. They also verify trusted source-mode/label propagation for SIP quote/history/market rows and the explicit offline marker, plain `BTC` stays on SIP while `BTC-USD` is normalized to Binance, U.S. history and earnings price movement use SIP bars while Nasdaq remains the EPS surprise source, and the legacy Node U.S. options route returns HTTP 410 without a public-provider call. Provider and store tests cover batching, coalescing, source classification, nanosecond/offset timestamp order, old-tick rejection, scoped REST watermarks, and freshness independent of session context.

The Playwright `market-stream.spec.ts` signs in through the local OIDC flow and exercises real Next routes with offline fixtures. It opens multiple tabs and Options widgets, verifies ACK and stale-tick behavior, waits for the regular chain snapshot poll without empty-membership cleanup, and delays an old-generation cleanup until after a newer renewal reaches the downstream mock. It also changes Gateway instance and coverage cap while holding the matching refreshed BFF response, proving the prior chain stays hidden and cannot renew an old-symbol lease until the new response is delivered; this check uses the actual response boundary rather than Gateway request counters. It treats fixture source metadata as unknown instead of claiming Alpaca. It also verifies stale/unauthorized status and browser-stream outage recovery to a newer SIP REST snapshot. The signed-in SIP 401/429 cases assert the failed `/api/quotes` request, visible widget error, Gateway request count, and absence of the research-provider fallback. The shared E2E Gateway fixture records subscription request order but always responds successfully; it does not assert the effective lease set after an out-of-order request. Rust Gateway code now rejects stale/equal conflicting option generations; cross-process Next-to-Rust lease acceptance, lease deadline and provider runtime evidence remain outside these offline browser fixtures.
