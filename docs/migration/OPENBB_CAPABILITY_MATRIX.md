# Native Research and OpenBB Capability Matrix

Status: Agent07 native implementation for this migration. This file records UI, route, permission, source and parity boundaries; it is not production/release acceptance and does not grant data redistribution rights.

## OpenBB boundary

EqoBoard's Rust Gateway keeps a separate OpenBB Workspace compatibility surface at `/widgets.json`, `/apps.json`, and `/openbb/*`. Its catalog registers SIP watchlist snapshots, OPRA option-chain snapshots, and SIP bars. Those JSON contracts are neither the native React registry nor the native workspace document. Native research widgets use static EqoBoard registrations, scoped read/action IDs, validated workspace widget configuration, and same-origin Next BFF routes. This migration does not embed OpenBB Workspace or add an OpenBB SDK/runtime dependency.

## Native acceptance rules

- All research provider requests originate in the same-origin BFF. Browser widgets call the scoped `WidgetDataClient` or the single closed `research.ai` action; they never fetch a provider URL or generic proxy.
- The data BFF has a closed GET operation allowlist, exact input fields, `research:read`, request deadlines, bounded response bodies, process-local cache/rate budgets and explicit unavailable/partial results. These in-process budgets do not provide distributed ingress enforcement. `research.ai`, private predictions and Engine reads use their own POST/permission or fixed-route contracts and do not inherit `research:read`.
- Provider envelopes retain source, provider URL/path, license declaration where known, provider `asOf`, independent `retrievedAt`, completeness, truncation, cache and warning. A cache hit is not a freshness claim. Provider-reported licenses are descriptive metadata, not data-use approval.
- Query definitions are validated by their static registration parser and saved only through the authenticated workspace config. Config validation limits filters/views/compare count and serialized size; query data results are not persisted as workspace state.
- Comparison never implies point-in-time synchronization. Each view retains source times, missing fields, partial failures and unknown completeness.
- A migration is not release acceptance until the fixed-head unit, route, permission, browser and container CI lanes pass. Tests authored here have not been executed locally; root owns unified CI evidence.
